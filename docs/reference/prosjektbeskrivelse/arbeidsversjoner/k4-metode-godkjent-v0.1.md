# K4 — Metode og forskningsetikk

> Denne filen er en godkjent arbeidsversjon. Den erstatter ikke det kanoniske kapitlet før endringen er flettet inn og loggført. Bruk ID-ene når tekst skal kommenteres, siteres eller revideres.

## Godkjent tekst

### K4-P1 — Forskningsløype

<a id="k4-p1-s1"></a>**[K4-P1-S1]** Prosjektet skal bruke en iterativ forskningsmodell.

<a id="k4-p1-s2"></a>**[K4-P1-S2]** Først utvikles en første versjon av beslutningsmodellen.

<a id="k4-p1-s3"></a>**[K4-P1-S3]** Den testes deretter i konkrete løsningsvalg, resultatene måles, og modellen justeres på grunnlag av funnene.

### K4-P2 — Datagrunnlag og dokumentasjonstillit

<a id="k4-p2-s1"></a>**[K4-P2-S1]** Først samles data fra produktkilder, dokumentasjon og pilotprosjekter.

<a id="k4-p2-s2"></a>**[K4-P2-S2]** Datagrunnlaget kan omfatte pris, EPD, FDV, levetid, vedlikehold, ombruksmulighet, kvalitet og dokumentasjonsstatus.

<a id="k4-p2-s3"></a>**[K4-P2-S3]** For hver opplysning registreres kilde, alder, enhet, produktnivå og dokumentasjonsstatus.

<a id="k4-p2-s4"></a>**[K4-P2-S4]** Statusen skal vise om opplysningen mangler, er estimert, bygger på generelle data eller er verifisert for den konkrete løsningen.

<a id="k4-p2-s5"></a>**[K4-P2-S5]** Reglene for status og dokumentasjonstillit fastsettes før piloteringen og brukes likt på alle alternativer.

<a id="k4-p2-s6"></a>**[K4-P2-S6]** Slik skal svake eller manglende data ikke skjules i en totalscore.

### K4-P3 — Flerkriteriemodell og metodevalg

<a id="k4-p3-s1"></a>**[K4-P3-S1]** Deretter utvikles en flerkriteriemodell som viser avveininger mellom pris, klima, levetid, kvalitet, vedlikehold, ombruk, dokumentasjon og risiko.

<a id="k4-p3-s2"></a>**[K4-P3-S2]** Prosjektet skal sammenligne aktuelle flerkriteriemetoder ut fra faste krav: hvor lett vektingen kan forklares, hvor følsomt resultatet er for endrede vekter, hvilke data metoden krever, hvordan manglende data håndteres, og om brukerne forstår resultatet.

<a id="k4-p3-s3"></a>**[K4-P3-S3]** På dette grunnlaget velges én metode eller en avgrenset metodekombinasjon for piloteringen.

### K4-P4 — Pilotering og måling

<a id="k4-p4-s1"></a>**[K4-P4-S1]** Modellen testes i reelle løsningsvalg.

<a id="k4-p4-s2"></a>**[K4-P4-S2]** Før piloteringen kobles hvert FoU-spørsmål til datakilde, målepunkt, sammenligningsgrunnlag og kriterium for vurdering.

| ID | Hva måles | Eksempel på målepunkt |
| --- | --- | --- |
| **K4-T1-R1** | Dataintegrasjon | Andel nødvendige felt som kan kobles, og behov for manuell behandling |
| **K4-T1-R2** | Livsløpssammenligning | Om levetid og vedlikehold kan omsettes til sammenlignbare kostnader |
| **K4-T1-R3** | Forklarbarhet | Om brukeren forstår hvorfor alternativene får ulike resultater |
| **K4-T1-R4** | Usikkerhet | Om brukeren oppdager manglende, generelle eller estimerte data |
| **K4-T1-R5** | Beslutningseffekt | Om grunnlaget endrer, bekrefter eller ikke påvirker valget |
| **K4-T1-R6** | Tidsbruk | Tid brukt sammenlignet med vanlig tilbudsarbeid |
| **K4-T1-R7** | Bankrelevans | Om den avtalte dokumentasjonen svarer på bankens definerte informasjonsbehov |
| **K4-T1-R8** | Skalering | Hvilke deler av modellen som kan overføres til en ny produktkategori |

### K4-P5 — Forskningsetikk og datahåndtering

<a id="k4-p5-s1"></a>**[K4-P5-S1]** Forskningsetikk og datahåndtering er en integrert del av metoden.

<a id="k4-p5-s2"></a>**[K4-P5-S2]** Prosjektet kan behandle brukerdata, kommersielt sensitive opplysninger og informasjon om beslutninger i pilotene.

<a id="k4-p5-s3"></a>**[K4-P5-S3]** Deltakerne skal få tydelig informasjon om formål, databruk, lagringstid og retten til å trekke seg.

<a id="k4-p5-s4"></a>**[K4-P5-S4]** Det skal samles inn minst mulig persondata, og forskningsdata skal anonymiseres eller pseudonymiseres før analyse.

### K4-P6 — Beslutningsansvar

<a id="k4-p6-s1"></a>**[K4-P6-S1]** VERIFIED skal være beslutningsstøtte, ikke en automatisk beslutningstaker.

<a id="k4-p6-s2"></a>**[K4-P6-S2]** Modellen skal ikke profilere personer eller ta kredittbeslutninger.

<a id="k4-p6-s3"></a>**[K4-P6-S3]** Endelig faglig og kommersiell vurdering ligger hos aktørene som bruker grunnlaget.

<a id="k4-p6-s4"></a>**[K4-P6-S4]** Prosjektet skal være åpent om datakilder, antakelser, svakheter og usikkerhet.

### K4-P7 — Videre planlegging

<a id="k4-p7-s1"></a>**[K4-P7-S1]** Forskningssikkerhet og datahåndteringsplan konkretiseres ved eventuell tildeling, mens søknaden skal beskrive prinsippene, risikoene og ansvarsdelingen.

## Åpne porter før innfletting

- Første produktkategorier må velges.
- Pilotens sammenligningsgrunnlag og baseline må defineres.
- Banken må definere konkret informasjonsbehov og beslutningssituasjon.
- Lars Gunnar må definere målepunktene for beslutningseffekt.
- Første MCDA-metode eller sammenligningsopplegg må velges.
- K4 må kvalitetssikres mot endelig WP-struktur når arbeidspakkene skrives.
