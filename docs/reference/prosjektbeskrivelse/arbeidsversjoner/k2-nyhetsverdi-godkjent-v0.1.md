# K2 — Nyhetsverdi

> Denne filen er en godkjent arbeidsversjon. Den erstatter ikke det kanoniske kapitlet før endringen er flettet inn og loggført. Bruk ID-ene under når tekst skal kommenteres, siteres eller revideres, for eksempel `K2-P4-S2` eller `K2-T1-R3`.

## Referansenøkkel

- `K2` = kapittel 2
- `P1` = avsnitt 1
- `S1` = setning 1 i avsnittet
- `T1` = tabell 1
- `R1` = rad 1 i tabellen
- Eksempel: `K2-T1-R4` betyr fjerde innholdsrad i første tabell

## Godkjent tekst

### K2-P1 — Hva nyhetsverdien er

<a id="k2-p1-s1"></a>**[K2-P1-S1]** VERIFIED er ikke først og fremst en ny app, miljømerking eller kalkulator.

<a id="k2-p1-s2"></a>**[K2-P1-S2]** Nyhetsverdien ligger i å utvikle og teste hvordan flere typer byggdata kan settes sammen til et forklarbart og etterprøvbart beslutningsgrunnlag i tilbudsfasen.

### K2-P2 — Eksisterende byggeklosser

<a id="k2-p2-s1"></a>**[K2-P2-S1]** Flere av de nødvendige byggeklossene finnes allerede.

<a id="k2-p2-s2"></a>**[K2-P2-S2]** Det finnes standarder for livsløpsvurdering og livsløpskostnader, og det finnes EPD-er, produktdata, FDV-data og metoder for å veie flere hensyn mot hverandre.

<a id="k2-p2-s3"></a>**[K2-P2-S3]** Tilgjengelighet, kvalitet og format varierer mellom datakildene.

<a id="k2-p2-s4"></a>**[K2-P2-S4]** De kartlagte standardene, datakildene, metodene og verktøyene dekker ulike deler av behovet.

<a id="k2-p2-s5"></a>**[K2-P2-S5]** De er i hovedsak rettet mot analyse, prosjektering, dokumentasjon eller enkeltkriterier, og er ikke dokumentert som ett samlet beslutningsgrunnlag for tilbudsfasen.

### K2-P3 — Hva VERIFIED skal undersøke

<a id="k2-p3-s1"></a>**[K2-P3-S1]** VERIFIED skal undersøke hvordan disse byggeklossene kan bli et enkelt, forklarbart og etterprøvbart beslutningsgrunnlag i tilbudsfasen.

<a id="k2-p3-s2"></a>**[K2-P3-S2]** Prosjektet skal teste om informasjonen kan gjøres anvendbar for mindre entreprenører og kunder før innkjøpet er låst.

### K2-P4 — Skillet mellom plattform og FoU-lag

<a id="k2-p4-s1"></a>**[K2-P4-S1]** Det nye FoU-laget er ikke selve VIBS-plattformen.

<a id="k2-p4-s2"></a>**[K2-P4-S2]** VIBS-plattformen kan brukes som testflate for prosjektet.

<a id="k2-p4-s3"></a>**[K2-P4-S3]** VERIFIED-laget er forskningsarbeidet: hvordan vekting, datakvalitet, usikkerhet og beslutningseffekt kan dokumenteres på en måte som tåler kontroll.

### K2-P5 — Forskningshullet

<a id="k2-p5-s1"></a>**[K2-P5-S1]** Forskningshullet kan beskrives med seks spørsmål.

#### K2-T1 — Hva dagens kunnskapsstatus ikke dokumenterer som en samlet løsning

| ID | Spørsmål | Forsiktig formulering |
| --- | --- | --- |
| **K2-T1-R1** | Kan flere datatyper kobles? | Eksisterende løsninger dekker ulike datatyper, men kartleggingen dokumenterer ikke én løsning som samler hele bredden. |

### K2-P6 — FoU-avgrensning og mulig verdi

<a id="k2-p6-s1"></a>**[K2-P6-S1]** VERIFIED skal ikke påstå at alle disse punktene er løst.

<a id="k2-p6-s2"></a>**[K2-P6-S2]** Prosjektet skal teste dem.

<a id="k2-p6-s3"></a>**[K2-P6-S3]** Dersom prosjektet lykkes, vil modellen kunne vise forskjeller, avveininger og usikkerhet mellom alternative løsninger.

<a id="k2-p6-s4"></a>**[K2-P6-S4]** Entreprenør og kunde skal fortsatt ta beslutningen.

<a id="k2-p6-s5"></a>**[K2-P6-S5]** Et slikt grunnlag kan også bli relevant for en bank som etterspør etterprøvbar prosjekt- og byggdokumentasjon.

<a id="k2-p6-s6"></a>**[K2-P6-S6]** Hvordan og i hvilken grad dette kan brukes, skal undersøkes mot ett avgrenset bankbehov i prosjektet.

## Åpne porter før innfletting

- Kartleggingen av nærmeste norske og europeiske verktøy bør få bedre uavhengig dekning.
- Påstander om bruk i tilbudsfasen, anvendbarhet for små entreprenører og beslutningseffekt må behandles som kunnskapshull eller FoU-spørsmål, ikke som dokumenterte markedsdommer.
- Banken må definere ett konkret informasjonsbehov og én beslutningssituasjon før banksporet låses.
- Forsikring og takst omtales bare som mulige senere skaleringsspor.
- Endringen må føres i endringsloggen når teksten flettes inn i det kanoniske kapitlet.
