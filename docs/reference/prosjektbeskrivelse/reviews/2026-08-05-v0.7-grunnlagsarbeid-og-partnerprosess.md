# Grunnlagsarbeid fram mot VERIFIED v0.7

**Dato:** 2026-08-05

**Status:** Arbeidsprogram etter det avgrensede v0.6-passet

**Styringsregister:** `2026-08-05-tilbakemeldingsregister-v0.6.md`

## Mål

Bygge et faglig og organisatorisk grunnlag som gjør en senere v0.7 til en mer
helhetlig søknadskandidat. Arbeidet skal løse åpne valg før de skrives som om de
allerede er besluttet.

## Port A – målgruppe, problem og prosjektkjerne

Avklar og dokumenter:

1. definisjonen av målgruppen, inkludert betydningen av «under ti ansatte»;
2. størrelse målt som antall foretak, sysselsetting og eventuell omsetning;
3. målgruppens brukerforutsetninger uten generalisering om kompetanse;
4. kundens informasjons- og kompetanseasymmetri i tilbudsfasen;
5. samfunnsmekanismen fra bedre løsningsvalg til klima, ressursbruk, levetid
   og feilrisiko.

**Leveranse:** kontrollert problem- og målgruppenotat med originalkilder og
presis bevisrolle.

## Port B – datamodell og avgrensning

Avklar:

1. hvilke beslutninger modellen skal støtte;
2. hvilke datakilder og informasjonsfelt som er relevante;
3. minste datakvalitet og hvordan mangler skal vises;
4. hvordan kompleksitet begrenses for små entreprenørbedrifter;
5. om leverandørsoliditet, konkursrisiko, garanti og reklamasjonsevne skal være
   del av kjerne, et eget spor eller utenfor prosjektet.

Leverandørsoliditet skal behandles som et reelt scopevalg. Det kan kreve
oppdaterte selskapsdata, regler for aktualitet, rettferdig behandling,
ansvarsavgrensning og et skille mot kredittvurdering.

**Leveranse:** beslutningsnotat for datadimensjoner, med eksplisitt inn/ut-scope.

## Port C – forskningsmetode og testdesign

Forskningspartneren skal bidra til å avklare:

1. forskningsdesign og korrekt fagterminologi;
2. hvordan modellen utvikles, valideres og justeres;
3. hvilke pilot- og testtyper som trengs;
4. hvordan entreprenørens og kundens forståelse og bruk måles;
5. hvordan beslutningspåvirkning kan tilskrives;
6. om og hvordan følsomhet, rangendringer og usikkerhet skal analyseres;
7. nødvendig nivå for forskningsetikk, datahåndtering og personvern.

**Leveranse:** metodebeslutning som kan kobles direkte til K3, K4 og
arbeidspakkene.

## Port D – kilder og state of the art

1. Lag en påstand–kilde-matrise for hele søknaden.
2. Finn en offentlig original for SMB-andel og bedriftsstørrelse.
3. Koble standardpåstander til konkrete standarder og tillatt bevisrolle.
4. Oppdater sammenligningen med Reduzer og andre relevante norske løsninger.
5. Be forskningsfaglig partner vurdere hvorfor FoU-gapet fortsatt er relevant.
6. Bevar Source Guard, sperreposter og gjenåpningsport.
7. Registrer hvert nytt kildefunn som kandidat før bruk.

**Leveranse:** kontrollert claim–source-matrise og oppdatert
konkurrentsammenligning. Bare Lars kan endre bruksstatus.

## Port E – virkninger og bærekraft

Avklar:

1. om prosjektet har ett hovedmål og ett sekundært bærekraftsmål, med konkret
   mekanisme og målepunkt;
2. hvilke klima-, ressurs-, levetids- og feilvirkninger som kan måles i
   prosjektperioden;
3. hvor langt kjemikalie-, helse-, sikkerhets- og sosiale data kan dekkes;
4. om V3 skal hete «Økonomiske virkninger» eller «Praktiske og økonomiske
   virkninger»;
5. hvilke økonomiske mekanismer som måles for entreprenør og kunde;
6. banksporets nøyaktige informasjonsbehov og avgrensning.

**Leveranse:** beslutningskart for V1–V3 og målepunkter.

## Port F – konsortium, arbeidspakker og budsjett

1. Bekreft hvem som fortsatt ønsker å delta.
2. Beskriv partnertyper og faktiske roller.
3. Innhent partnernes egne bidrag, ressurser og begrensninger.
4. Utform arbeidspakker sammen med forsknings- og gjennomføringspartnerne.
5. Koble hver arbeidspakke til FoU-spørsmål, leveranse, milepæl, ansvar og
   kostnad.
6. Bygg budsjettet etter faktisk arbeidsfordeling og støttekrav.

**Leveranse:** partner- og arbeidspakkekart samt budsjettgrunnlag.

## Partnerprosess

### Før felles møte

- Send kort status og varsel om ny oppstart.
- Lag et partnernotat på 2–4 sider med prosjektkjerne, status, åpne spørsmål og
  ønsket bidrag.
- Legg ved partnerlesbar v0.6 som bakgrunn, tydelig merket som arbeidsutkast.
- Skill de få søknads-/metodevurdererne fra data-, leverandør- og
  pilotbidragsytere, og gi hver gruppe avgrensede spørsmål.
- Be én erfaren evaluator/rådgiver om forhåndssparring på søknadslogikk og
  mangler.
- Be forskningsfaglig kontakt vurdere metode, testdesign og FoU-høyde.
- Bruk en kort skriftlig brief som hovedinngang. Et eventuelt opptak er
  tilleggsbakgrunn og krever avklart samtykke og formål.

### Felles oppstart, 30–40 minutter

1. Hvor prosjektet står.
2. Hva som nå er låst.
3. Hva som skal avklares med partnerne.
4. Hvem som følges opp individuelt og om hva.
5. Dato for ny status.

Møtet brukes til informasjonsflyt og forankring. Linjeredigering og detaljert
arbeidspakkefordeling gjøres i mindre arbeidsmøter.

## Rollefordeling

- **Lars:** beslutninger, partnerkontakt, kildeport og ekstern sending.
- **Claude:** orkestrering, strukturkritikk, alternative formuleringer og
  seksjonsvise utkast etter beslutning.
- **Codex:** repo, feedbackregister, påstand–kilde-kobling, versjoner, diff og
  kontrollporter.
- **Forskningspartner:** forskningsdesign, testopplegg, FoU-høyde og metode.
- **Erfaren evaluator/rådgiver:** leser som panel og peker på mangler og
  overstrekk.
- **Sonar/nettsøk:** finner kandidater og originaler; avgjør ikke kildestatus.

## Rekkefølge fram mot v0.7

1. Fullfør og godkjenn det avgrensede v0.6-passet.
2. Send partnernotat og gjennomfør forhåndssparring.
3. Hold kort oppstartsmøte og bekreft deltakelse.
4. Løs port A–F med én beslutning og én eier om gangen.
5. Oppdater beslutnings- og kilderegister.
6. Opprett v0.7 som ny fil. Bevar v0.6 som sendt arbeidsgrunnlag.
7. Rediger v0.7 seksjonsvis.
8. Kjør kilde-, språk-, metode-, kriterie- og innflettingskontroll.
9. Lars godkjenner før ekstern bruk eller kanonisk innfletting.

## Ikke-mål

- Ikke la et stort partnermøte skrive søknaden kollektivt.
- Ikke gi nye kilder status gjennom redigering.
- Ikke fastsett metode, testprotokoll eller arbeidspakker uten faglig eier.
- Ikke bland partnerforpliktelser med uformell interesse.
- Ikke overskriv v0.6 når v0.7 opprettes.
